# Public Groups list, and Group join requests that create Community membership

Play now happens inside Groups. The Games hub no longer shows public pickup, so Users need a way to find a squad. The **Public Groups list** is that surface: live Public padel Groups the viewer is not in — Loose Group Public, and Club Group Public in live Communities, including Community Private.

Listing Club Group Public from Community Private reveals Group and Community names to every authenticated User and opens a path into that Community. That is deliberate. Staff who want a hidden club keep its Groups Private. The Directory stays a planned Community list and is not this surface.

A **Group join request** may create Community membership. A non-Member requesting a Club Group Public is always a request, even when Require approval is off. Approving it admits them as Community Member (role member) and Group member in one transaction, and marks any pending Community join request approved. That is also how a User enters a Community Private through one of its Public Groups. Community Private still has no request-to-join on the Community itself.

Lookup invites and Invite links still admit directly and never go through approval.

**Considered Options**: keep Groups unlistable and rely on URL sharing; list Communities instead; refuse non-Member Club Group requests unless Require approval is on. Rejected: URL-only discovery does not replace the hidden Public Games tab; a Community Directory is still planned and separate; always-request for non-Members is the chosen path into a Private Community's Public Groups.
