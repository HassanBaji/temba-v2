# App-owned Onboarding questionnaire, gated on Postgres

New Users reach Home with no Level and no stated Position preference. Clerk owns account creation, so the questions could ride inside `<SignUp>`; but both answers are read by the server (seat pre-selection, `ratings.me`, later matchmaking), and the Level question must call the shipped `ratings.selfDeclare` rules, which Clerk cannot. **The questionnaire is an App-owned step at Route `/onboarding`**, its answers stored in Postgres (`user.preferred_position`, `user.onboarding_completed_at`, and the existing `ratings` row), and the gate lives in `dashboard/layout.tsx` — not in `middleware.ts`, which runs on the edge runtime and cannot read Postgres. Invite routes stay ungated so a 6-hour Invite link token is never spent waiting on a questionnaire; the accept's `/dashboard/**` landing becomes the `redirect_url` out of onboarding.

**Considered Options**: Clerk custom fields / `unsafeMetadata`; middleware gate on a Clerk session claim mirroring completion; a dismissible Home prompt with no gate; a `user_profile` table. Rejected: Clerk fields cannot express a two-step resumable flow or reuse `selfDeclare`, and leave server-queried data outside the database; a session-claim mirror duplicates the source of truth and needs token customisation; a dismissible prompt leaves the long tail of Users with no Rating, which is the problem; a table for two nullable columns is a join for nothing. Level seeding is unchanged — ADR-0009 already seeds a declared Level at φ₀ = 350, which keeps a declared User Provisional and correcting fast. Details: `.scratch/onboarding-questionnaire/spec.md`.
