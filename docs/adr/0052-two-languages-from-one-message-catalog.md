# Two languages from one message catalog in `@repo/i18n`

Temba ships in English and Arabic. Every user-facing string in the Web App, the Mobile App and the copy modules of `@repo/domain` is read from one catalog, the new `@repo/i18n` Package, keyed by property access (`messagesFor(locale).game.joinAction`). The catalog is TypeScript data: one file per owning feature and App slice under `src/messages/en/` and `src/messages/ar/`, leaves are strings or functions of their variables, and the Arabic files are typed `satisfies typeof <english file>` so a missing or extra key fails `typecheck`. Counts go through `plural()`, which uses `Intl.PluralRules` for the six Arabic categories. The locale is a value, never ambient: domain functions that return copy take `locale` as their last required parameter, Client Components read it from a provider, and Server Components read it from the request. Arabic keeps Latin digits (`ar-BH-u-nu-latn`) so scores, prices and Levels stay in Archivo's tabular figures. The Web App stores the choice in the `temba-locale` cookie and sets `lang` and `dir` on `<html>`; the Mobile App stores it in AsyncStorage, defaults to the device language, and mirrors layout through `I18nManager`, which applies on the next launch.

**Considered Options**: `next-intl` and `react-i18next` with JSON catalogs and string keys; a global current-locale variable read by the domain copy functions; translating at the edge from the English output of the domain modules; message catalogs inside `@repo/domain`. String-keyed libraries give up the type safety the TypeScript catalog has for free and need two runtimes for the two client stacks. A global locale is unsafe on the server, where concurrent requests render in different languages. Translating English output breaks on every interpolated sentence. Keeping the catalog inside `@repo/domain` would avoid a new Package, but copy for the two Apps' own chrome is not a domain rule, and one data-only Package that translators edit without touching logic mirrors `@repo/design-tokens`. The one boundary change is `@repo/domain ──► @repo/i18n`; `@repo/i18n` itself imports nothing from the Workspace. Legal text (`terms.ts`) stays English and says so, since a machine translation of a contract is not a contract. Server error messages still arrive in English; translating them is a later ticket on the API context.
